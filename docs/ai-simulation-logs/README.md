# AI 시뮬레이션 로그 운영 규칙

## 1. 목적

AI 시뮬레이션 로그는 다음 정보를 팀이 재검토하고 인수인계할 수 있도록 보존한다.

- AI 에이전트가 수행한 작업 단위 추적
- 변경 이유와 의사결정 보존
- 팀원 간 작업 인수인계
- 검증 명령과 결과 기록
- 오류와 후속 작업 추적

로그는 에이전트의 비공개 내부 추론을 저장하는 문서가 아니다. 관찰 가능한 요청, 작업 전 상태, 변경 파일, 결정, 검증 결과와 남은 위험만 기록한다.

## 2. 팀원 디렉터리

| 팀원 | 경로 |
|---|---|
| 정이량 | [`docs/ai-simulation-logs/jeong-iryang/`](jeong-iryang/README.md) |
| 황대겸 | [`docs/ai-simulation-logs/hwang-daegyeom/`](hwang-daegyeom/README.md) |

공통 로그 형식은 [중앙 로그 템플릿](_template.md)을 사용한다.

## 3. 파일명 규칙

각 팀원 폴더에서 독립적으로 4자리 증가 번호를 사용한다.

```text
0001-short-task-name.md
0002-short-task-name.md
0003-short-task-name.md
```

- 작업명은 영문 소문자 kebab-case로 작성한다.
- 번호는 해당 팀원 폴더에서만 증가시킨다.
- 두 팀원이 각각 독립된 폴더에서 번호를 관리하므로 동일 번호가 존재해도 문제없다.
- 작업 시작 전에 팀원 폴더의 `README.md`에 적힌 다음 번호와 실제 파일 목록을 함께 확인한다.

## 4. 로그 생성 단위

하나의 의미 있는 작업 결과마다 로그 하나를 생성한다.

로그를 생성해야 하는 예:

- 기능 추가
- 버그 수정
- 스키마 변경
- 데이터 모델 결정
- 환경 또는 의존성 변경
- 테스트 및 검증 결과
- 브랜치 운영 결정
- 대규모 분석 또는 리팩터링
- 실패한 접근과 중단 결정

다음 작업은 기존 로그에 간단히 반영하거나 생략할 수 있다.

- 오탈자 한 글자 수정
- 코드 변경 없는 단순 질문
- 동일 작업 내 반복 검증
- 생성물 없는 단순 상태 확인

여러 작업이 하나의 요청에 포함되더라도 같은 목적과 결과로 묶이는 경우 하나의 로그로 기록할 수 있다. 목적·산출물·검증 기준이 달라지면 별도 로그로 나눈다.

## 5. 작성 규칙

- 에이전트의 비공개 내부 추론을 기록하지 않는다.
- 관찰 가능한 작업, 결정, 파일 변경, 검증 결과만 기록한다.
- 실제 비밀번호·토큰·개인정보를 기록하지 않는다.
- 실행하지 않은 테스트를 통과했다고 기록하지 않는다.
- 추측과 확인된 사실을 구분한다.
- 완료되지 않은 작업과 남은 위험을 숨기지 않는다.
- 가능한 경우 관련 브랜치·커밋·PR을 연결한다.
- 기존 로그는 원칙적으로 수정하지 않는다.
- 사실 오류를 수정해야 하면 수정 사유와 날짜를 로그 하단에 남긴다.
- 변경 파일이 없으면 변경 파일 표에 `없음`이라고 명시한다.
- 검증 명령이 실행되지 않았으면 결과에 `미실행`과 이유를 기록한다.
- 실패한 명령은 생략하지 않고 오류와 후속 조치를 기록한다.

## 6. 권장 작성 절차

1. 작업 전 브랜치와 `git status --short --branch`를 확인한다.
2. 해당 팀원 폴더에서 다음 번호를 확인한다.
3. [_template.md](_template.md)를 복사하여 작업 로그를 만든다.
4. 요청 범위와 작업 전 상태를 먼저 기록한다.
5. 변경 파일과 주요 결정을 작업 중 또는 직후 기록한다.
6. 실제로 수행한 검증 명령과 결과를 기록한다.
7. 남은 위험과 다음 작업을 기록한다.
8. 팀원 폴더 README의 다음 로그 번호를 갱신한다.
9. 커밋 또는 PR을 만든 경우 로그의 관련 필드를 후속 갱신한다.

## 7. 보안 및 개인정보

다음 항목은 로그에 기록하지 않는다.

- 실제 비밀번호와 인증 토큰
- `.env`의 실제 값
- 개인 이메일과 전화번호
- 비공개 저장소 접근 키
- 로컬 사용자 홈의 불필요한 개인 경로
- AI 에이전트의 비공개 내부 추론

환경변수 이름, 안전한 자리표시자, 공개 문서 링크와 Git 커밋 해시는 기록할 수 있다.
