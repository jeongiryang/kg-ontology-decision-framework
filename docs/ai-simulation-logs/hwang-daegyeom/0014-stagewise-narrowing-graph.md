## 1. 작업 목적

work.txt 5번의 핵심인 "실제 탐색이 일어나는 모습"을 처리 중 화면에서 보이게 하는 것과,
리뷰어가 읽을 계약 문서를 PR에 넣는 것이다.

## 2. 요청 내용 요약

시간순으로 정리한다. 뒤 요청이 앞 요청을 좁힌다.

1. `docs/evidence-chat.md`에 탐색 그래프 계약을 반영하라. 지금 하라. 리뷰어가 읽을
   문서가 PR에 빠져 있으면 안 된다.
   - **별도 커밋으로 분리**하라(docs only). #32도 같은 파일을 건드리므로 리베이스 때
     이 커밋만 따로 다루면 된다.
   - 담을 것은 **계약이지 후일담이 아니다.** 설계 경위는 ADR 0011·0013에 있으니 링크만
     걸고 반복하지 마라.
2. (작업 중 추가 지시) 두 가지를 고친다. work.txt 5번의 핵심이라 #33에 추가 커밋으로
   넣는다. 리뷰가 아직 시작 안 됐으니 지금 넣는 게 맞다.
   - **배율 표기를 줄여라.** 화면에는 `실측 8.9ms`만 남기고, 늘려 재생한다는 사실은
     재생 버튼 tooltip으로 내리고, 배율 숫자는 화면에서 빼라. 진행 중 화면은 실측
     그대로이므로 안내 문구 자체가 필요 없다.
   - **진행 중 화면에서 그래프가 자라나게 하라.** hop 단위 중계가 불가능한 것이지
     (ADR 0013), 파이프라인 단계 단위 중계는 가능하다. 9단계 각각에서 그래프에 무엇이
     나타나는지를 지정.
   - 지어내지 않기: 각 단계에서 그리는 것은 그 단계가 실제로 보고한 값에서만 온다.
     아직 모르는 것은 그리지 마라. 실패하면 그 자리에서 멈춰라.
   - `질의가 그래프를 밟는 순서`와 `시스템이 답을 좁혀 가는 과정`은 다른 것이다.
     화면 문구로 그 차이를 밝혀라. 둘을 같은 것처럼 말하지 마라.
   - 검증: 단계 이벤트 도착 시점의 스크린샷을 연속으로(9장) 찍어라. 되묻기 케이스는
     조회가 없으므로 그 이후로 진행되지 않는 것을 확인하라.

## 3. 작업 전 상태

- PR #33은 `d8fe946`까지 올라가 draft 해제되고 `jeongiryang` 리뷰 요청 상태였다.
- 처리 중 화면은 승인 그래프(`CLAIM_BUILDING`의 `traversal_graph` 또는 `NEO4J_EXPLAIN`의
  `query_graph`)가 도착한 뒤에야 그래프를 그렸다. 그 전에는 한 줄 자리표시만 있었다.
- `docs/evidence-chat.md`의 「inspection 그래프 projection」절은 탭 3개·2줄 말줄임 등
  이미 없어진 구현을 서술하고 있었다.
- 결과 화면 재생 문구는 `실측 8.9ms · 사람이 볼 수 있도록 1356배 느리게 재생 중`이었다.

## 4. 수행한 작업

### 4.1 계약 문서 반영 (`58bec75`, docs only)

`docs/evidence-chat.md`를 계약 기준으로 고쳤다. 없어진 구현을 서술하던 문장도 함께
바로잡았다(탭 3개 → 단일 그래프, `=true` → 3값, 실패 후보 비공개 → 배지와 함께 공개).

### 4.2 배율 표기 축소 (`6596c9e`)

화면에는 `실측 N.Nms`만 남기고, 배율 숫자를 뺐다. 늘려 재생한다는 사실은 재생 버튼
tooltip으로 내렸다. 진행 중 화면은 문구 자체를 숨겼다(`note.hidden = !slowed`).

### 4.3 단계마다 자라는 그래프 (`6596c9e`)

`NARROWING_STAGES` 9개 정의, `narrowingProgress()`, `narrowingGraph()`,
`renderNarrowingPanel()`을 추가하고 처리 중 화면 분기를 이것으로 교체했다.
`renderProgress()` 끝에서도 패널을 갱신해, `inspection_update`가 따로 오지 않는
단계에서도 그림이 그 자리에서 멈추게 했다.

후보 노드를 한국어로 그리기 위해 `SCHEMA_SELECTION`에 `label_names_ko`를 공개했다.
값은 `ontology_spec.json`의 `name_ko`이며 별도 사전을 두지 않는다. `PUBLISHED_FIELDS`와
계약 테스트 허용 목록에 함께 등록했다.

### 4.4 요구와 달라진 두 곳

지시대로 구현하면 지어내야 해서 실제 보고값에 맞춰 옮겼다. 4.5절 근거 참고.

| 요구 | 구현 | 이유 |
|---|---|---|
| 3단계에 후보 사라짐 | 5단계 | `CYPHER_GENERATION`·`STATIC_VALIDATION`은 어느 노드를 쓰는지 보고하지 않는다 |
| 6단계에 실제 이름 | 8단계 | `GRAPH_EXECUTION`은 행 수와 operator 실측만 보고한다 |

3·4단계는 그림을 바꾸지 않고, **바꾸지 않는 이유**를 화면 문구로 적었다.

### 4.5 브라우저 검증이 잡은 결함 3건

| 결함 | 증상 | 조치 |
|---|---|---|
| 되묻기가 `9/9`로 표시 | 그림은 자리표시 하나뿐인데 다 밟았다고 표시 | 완료 단계를 그냥 세던 것을 **이어진 단계만** 세도록 수정 |
| 노드 겹침 | `Department`와 `EducationGoal`이 둘 다 `(70,216)` | 같은 줄 안에서 `xGap` 이상 벌어지도록 자리를 밀어 줌 |
| 좌표 `NaN` | 콘솔 오류 54건 | 길이 0 간선의 `0 * Infinity`. `trim()`이 유한값만 돌려주게 막음 |

뒤 두 건은 이번 변경 이전부터 있던 것이다. `git checkout HEAD -- app.js`로 되돌려 같은
질의를 실행해 54건이 그대로 나오는 것을 확인한 뒤 고쳤다.

### 4.6 검증 스크립트

`scripts/verify_narrowing_stages.py`를 추가했다. `.narrowing-stage` 문구가 바뀔 때마다
한 장씩 찍는다. **문구가 바뀌지 않으면 찍지 않는다.** 남은 장수가 곧 그림이 실제로
달라진 횟수이며, 단계 수를 채우려고 같은 그림을 여러 장 찍지 않는다.

## 6. 주요 결정과 이유

- **문서를 docs 단독 커밋으로 분리했다.** #32가 같은 파일을 건드려 리베이스 때 이 커밋만
  따로 다룰 수 있어야 한다. 담당자 지시다.
- **검증 경계를 완화하지 않았다.** 3단계에서 경로를 그리려면 정적 검증 단계에서
  `path_edges`를 공개해야 하는데, 이는 "정적 검증과 EXPLAIN을 **모두** 통과한 뒤에만
  Cypher를 승인한다"는 기존 계약을 깨는 것이다. 시각화를 위해 완화하지 않았다.
- **눈에 보이는 변화 9번을 만들지 않았다.** 실측 결과 9단계 중 2개가 전체의 99.7%를
  쓰고 5~9단계는 13ms 안에 끝난다. 나눠 보이려면 지연을 넣어야 하는데
  "시간 늘리지 마라"와 충돌한다. 대신 실행 중인 단계를 `N/9 ... 진행 중`으로 적어
  6.5초 걸리는 구간에서 화면이 멈춘 것처럼 보이지 않게 했다.
- **스크린샷 9장을 만들지 않았다.** 그림이 달라지지 않은 단계를 찍으면 같은 장면이
  중복된다. 달라질 때만 찍고, 3장이 나온 사실을 그대로 적었다.
- **되묻기 `9/9` 결함은 이번 변경이 만든 것이다.** 완료된 단계를 세는 첫 구현이
  원인이었고, 브라우저 실측으로 발견해 고쳤다. 감추지 않고 남긴다.

## 8. 발견된 문제와 위험

- 노드 겹침과 `NaN` 좌표는 이번 변경 이전부터 있었고 `node --check`와 단위 테스트를
  모두 통과했다. 브라우저 검증으로만 드러났다. 이 종류의 결함은 앞으로도 같은 방법으로만
  잡힌다.
- `label_names_ko`는 `SchemaCatalog.from_generated()`를 매 요청 호출한다. 실패하면 빈
  맵을 돌려주고 영문 원형이 그대로 표시된다. 캐시는 두지 않았다.
- 캡처 C는 실행 시점에 따라 관측 상태 수가 달라진다(1~3). LLM 응답 시간에 좌우된다.
