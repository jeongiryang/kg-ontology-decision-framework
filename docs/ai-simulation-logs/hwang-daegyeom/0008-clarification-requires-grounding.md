## 1. 작업 목적

0007에서 만든 연쇄 되묻기가 **뜻 없는 입력까지 답변으로 데려가는** 것을 담당자가 화면에서
발견했다. 이 로그는 그 결함의 원인과 수정, 그리고 결함을 보이게 만든 화면 변경을 남긴다.

0007과 목적이 다르다. 0007은 "답할 수 있을 때까지 이어 가기"였고, 이것은 "이어 갈 자격을
두기"다. 방향이 반대쪽으로 한 번 접힌 셈이라 별도 로그로 나눈다.

## 2. 요청 내용 요약

1. "질문을 뭐 했는지 까먹잖아. 그러니까 답변이 되었으면 어떤 질문 → 선택지를 선택해서
   답변이 되었는지 그것도 표시하게 다시 만들어줘."
2. (화면 캡처와 함께) "어떤 게 문제인 거 같음?" — 입력이 `ㅇ런아러` 인데
   `무엇을 알고 싶으신가요? → 교육목표` 를 거쳐 `검증된 답변` 이 나온 화면.
3. "진행해줘" — 진단과 수정안을 보고한 뒤 승인.

요청 1이 요청 2를 가능하게 했다. 경로를 화면에 남기지 않았다면 답변만 보고 지나갔을
결함이다.

## 3. 작업 전 상태

- 0007 종료 시점. 연쇄 되묻기가 동작하고 자연어 21문항 범위 안 17/19.
- 답변 화면은 `추가로 지정한 조건 N개를 함께 조회했습니다` 라고만 알렸다. **그 N개가
  무엇이었는지 화면에 없었다.**
- 되묻기 선택지는 계획이 서지 않으면 언제나 무언가를 내놓았다.

## 4. 수행한 작업

### 4.1 답변 화면에 걸어온 경로를 남김

원래 질문 아래에 **되물은 문구 → 고른 것**을 순서대로 쌓는다.

```text
❝ 과목 알려줘 ❞
  ↳ 무엇을 알고 싶으신가요? → 학사규칙
  ↳ 어떤 이수요건을 말씀하시나요? → 균형교양 4개 영역에서 영역별로 각 1과목 이상 이수한다.
  [답변] 균형교양 4개 영역에서 영역별로 각 1과목 이상 이수한다.
```

브라우저의 `clarify` 상태에 `trail` 을 더했다. **서버로 보내지 않고 조회에도 관여하지
않는다.** 조회 조건은 종전대로 `resolved` 가 들고, 서버가 선택지를 다시 만들어 대조하는
검증도 그대로다.

### 4.2 결함 발견

경로가 보이자 담당자가 즉시 이상을 지적했다. 재현 결과는 다음과 같다.

| 입력 | 수정 전 |
|---|---|
| `ㅇ런아러` | 선택지 5개 → 답변 (근거 12건) `검증된 답변` |
| `asdfasdf` | 선택지 5개 → 답변 (근거 12건) `검증된 답변` |
| `ㅋㅋㅋㅋㅋ` | 선택지 5개 → 답변 (근거 12건) `검증된 답변` |
| `오늘 점심 뭐 먹지?` | `OUT_OF_SCOPE` (정상) |

**뜻 없는 입력이 뜻 있는 범위 밖 질문보다 더 잘 통과했다.** 말이 되는 질문은 계획 모델이
범위 밖으로 걸러 내지만, 뜻 없는 입력은 계획 모델이 `CLARIFICATION_REQUIRED` 를 내고 그
자리를 되묻기가 받아 주었기 때문이다.

답변에 쓰인 사실 12건은 모두 진짜 `VERIFIED` 근거였다. 거짓이어서 틀린 것이 아니라
**아무도 그것을 묻지 않았기 때문에** 틀린 답이다.

### 4.3 원인

`ClarificationChoices._intents()` 의 되돌림이다.

```python
modes = self._index.leading_modes(question, ...) or tuple(EXTENDED_FAMILIES)
```

검색이 아무것도 못 찾으면 **선언된 fact family 전체**를 목록으로 되돌려 주었다. 0006에서
"고를 것이 언제나 하나는 나와야 한다"고 넣은 자리인데, 0007이 연쇄를 얹으면서 이것이
"질문이 무엇이든 메뉴를 준다"가 됐다.

선택지를 만드는 근거가 **"질문이 데이터를 가리키는가"가 아니라 "계획이 서지 않았는가"**
였다. 이 둘은 다른데 한 자리에서 처리되고 있었다.

### 4.4 수정 — 되묻기에 자격을 둠

두 곳을 고쳤다.

- `_intents()` 의 되돌림을 없앴다. 검색 후보가 없으면 선택지를 만들지 않는다.
- `LocalQueryPlanner._points_at_nothing()` 을 추가하고, 적재된 어느 사실과도 겹치지 않는
  질문은 **계획 모델을 부르기 전에** `OUT_OF_SCOPE` 로 끝낸다. `안전 처리 실패` 가 아니라
  범위 밖이라고 말하는 것이 사실에 맞고, LLM 호출도 줄어든다.

되묻기로 값을 고른 뒤에는 이 검사를 하지 않는다. 그 값 자체가 적재 데이터에서 나왔고 이미
서버가 대조해 통과시킨 것이라, 질문 문장이 짧아도 가리키는 사실이 있다.

### 4.5 정적 파일 캐시

`app.js`·`app.css` 도 `Cache-Control: no-store` 로 내려보낸다(`_FreshStaticFiles`).
0006에서 `index.html` 만 막아 두었는데, 새 문서가 예전 스크립트를 부르면 같은 증상이
반복된다.

### 4.6 테스트 갱신

바뀐 계약에 맞춰 5건을 고쳤다. 소급해서 지운 것이 아니라 **계약이 바뀐 것**이다.

| 테스트 | 종전 계약 | 새 계약 |
|---|---|---|
| `test_clarification_always_offers_something_to_pick` | 뜻 없는 입력에도 선택지를 준다 | 가리키는 사실이 있는 질문이면 준다 |
| `test_meaningless_question_never_returns_every_rule` → `test_a_meaningless_question_is_out_of_scope_not_a_menu` | 되묻기로 끝난다 | 범위 밖으로 끝나고 **선택지도 없다** (3개 입력 검사) |
| `SettledScopeTests::test_an_intent_the_data_cannot_settle_still_asks_back` | `그거 알려줘` | `교양 그거 알려줘` (가리키는 사실이 있는 입력으로) |
| `PlanningDiagnosticsTests::test_every_attempt_is_recorded...` | `무엇이든 알려줘` | `교양 학점 알려줘` |
| `test_planner_ambiguity_and_scope_statuses_do_not_create_plan` | `질문` | `교양 학점은?` |

진단 테스트의 `assertIn("SINGLE_COURSE", record.contract_error)` 는

기록된다"이지 특정 문장이 아니며, 질문을 바꾸면 걸리는 계약이 달라지기 때문이다.

## 6. 주요 결정과 이유

### 6.1 문턱값이 아니라 후보 유무로 막는다

BM25 점수는 정규화돼 있지 않아 절대 문턱값이 깨지기 쉽다. 실측해 보니 뜻 없는 입력은
점수가 낮은 것이 아니라 **후보가 0건**이었다. 겹치는 토큰이 하나도 없기 때문이다. 그래서
문턱값을 두지 않고 "후보가 있는가"만 본다.

| 입력 | 상위 점수 | 후보 수 |
|---|---|---|
| `ㅇ런아러` | 0.000 | 0 |
| `asdfasdf` | 0.000 | 0 |
| `ㅋㅋㅋㅋㅋ` | 0.000 | 0 |
| `과목 알려줘` | 4.720 | 5 |
| `교양 이수요건은?` | 14.270 | 5 |
| `컴퓨터공학과 전공능력은 무엇인가?` | 23.186 | 5 |

### 6.2 손실을 먼저 재고 적용했다

담당자에게 "지금 되묻기로 넘어가던 애매한 질문 일부가 거절로 바뀔 수 있다"고 알린 뒤
적용 전에 측정했다.

- 정상 질문 32개 중 **31개 통과**. 걸린 하나는 `시간표 알려줘` 로, 적재 데이터에 그 개념이
  없어 거절이 맞는 경우다.
- 뜻 없는 입력 10개 중 **9개 차단**. 통과한 하나는 `테스트테스트` 로 후보 2건이 잡혔다.

### 6.3 화면 기록은 서버로 보내지 않는다

`trail` 은 표시용이다. 조회에 쓰이면 사용자가 조작한 문자열이 조회 근거가 된다. 조회
조건은 종전대로 `resolved` 만 쓰고 서버가 다시 만들어 대조한다.

## 8. 발견된 문제와 위험

- **`테스트테스트` 같은 입력은 여전히 통과한다.** 한글 2-gram이 우연히 걸리는 경우가
  있다. 후보 수가 적은 경우까지 막을지는 정하지 않았다.
- **후보 0건 판정은 색인 어휘에 의존한다.** 적재 범위가 넓어지면 지금 거절되는 입력이
  통과할 수 있고, 반대로 데이터에 없는 개념을 묻는 정상 질문(`시간표 알려줘`)은 계속
  거절된다. 후자는 의도한 동작이나, 화면에 "그 개념은 이 자료에 없다"고 구분해 알리지는
  않는다.
- `node --check` 를 실행하지 못했다. 화면 스크립트는 자동 검사 없이 실서버 동작으로만
  확인했다.
- 담당자의 화면 실측은 4.1 변경분까지만 이뤄졌다. 4.4 수정 이후 화면은 아직 확인하지
  않았다.
